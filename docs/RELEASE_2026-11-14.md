# Sweep Calculator — Development Release (2026-11-14)

## Scope

This release implements the eight requested operational areas in the `cloud-v2.js` frontend and live Supabase schema. Production records were preserved. User-directed manual/paid testing has **not** been carried out; only static JavaScript checks and read-only database function/permission checks were used during development.

1. **Player Wallet:** workspace-unique normalized player names, full UUID identity, search, new-player badges, full paginated load/cash-out history; no initial/default player bonus setting.
2. **Loads:** per-transaction manually entered bonus percentage (no player default) with rate snapshots, optional notes, audited 15-minute worker self-corrections, manager approval for later corrections, affected closing periods reopened for review.
3. **Cash-Out:** platform-wide rules, owner review/status, notifications and audit log, backend point credit ticker, fee and backend purchase-rate snapshots.
4. **Backend Closing:** Manager-only finalization, baseline, owner-editable cutoff/timezone, daily schedule with 30-minute grace and late alert, mismatch checks including reloads and cash-out credits, notes, Owner approval and latest-balance correction audit.
5. **Payment Closing:** historical provider expected-net vs entered actual settlement, fee-bearer handling, discrepancy statuses, stale flags after transaction corrections, Owner approval.
6. **Reports:** database-generated daily/weekly/monthly full-history summaries, estimated operating margin vs cash flow, loader performance, paginated CSV exports and audit exports.
7. **Owner Settings:** platform cash-out rules and editable daily cutoff with timezone.
8. **Manager Portal:** Loader performance with login labels, missing/irregular transaction indicators from closing mismatches, review queues, backend live ticker.

## Security

- Permission escalation through direct membership writes was blocked.
- Financial transactions, approvals, audit trails and reconciliations require the validated RPC functions.
- Broad team RLS `ALL` policies were changed to restrictive guards; allowed read/write actions require explicit per-operation policy.
- Cash-out view is read-only and includes fee snapshots.

## Accounting semantics

Estimated operating margin uses per-load point cost snapshots and per-cash-out backend rate snapshots, deposit/owner-borne processing fees, cash-outs and expenses. Cash flow uses actual backend point purchases (reloads), not unsold inventory valuation. A final audited profit statement requires accounting reconciliation and the owner's manual verification.

## Correction — 2026-11-14: Bonus settings removed

The user explicitly rejected all initial/default/per-player bonus configurations. **Creating a player collects only the name/ID.** Every new Load requires an independently entered bonus percentage (including an explicit `0` for no bonus); nothing is carried over from previous loads. The server calculates the transaction's points from its payment and submitted bonus only. Load corrections can change the original transaction's bonus subject to existing correction/approval rules. The earlier player-level bonus function and database column were dropped, and old transactions were preserved. Superseding SQL: `migrations/20261114_remove_default_bonus_transaction_only.sql`.

## Correction — 2026-11-14: Load bonus calculation from entered points only

The user confirmed that loaders must enter **Payment Received ($)** and **Points Loaded**; **Extra Bonus Points = Points Loaded − Payment Received**. For example, a $20 payment with 24 points credited has 4 extra points. A $50 payment with 100 points credited has 50 extra points. **No percentage is entered, stored, displayed or requested in the Load/Correction workflow.** The server validates both amounts and computes differences from the actual amounts. The New Load form, the 15-minute correction flow, and manager approvals now use points. Existing player and load records remain unchanged. The superseding DB migration is `migrations/20261114_load_received_vs_actual_points.sql`.
